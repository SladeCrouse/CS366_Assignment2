# Assignment 2 — Semantic Segmentation with UNet++ on Oxford-IIIT Pet

This project trains a three-class UNet++ segmentation model with PyTorch Lightning. The trimap labels are mapped as follows:

- Original value `1` → class `0` (`pet`)
- Original value `2` → class `1` (`background`)
- Original value `3` → class `2` (`border`)

Images are resized with bilinear interpolation; masks are always resized with nearest-neighbor interpolation. The default input size is 256×256 to keep training practical. Use `--image-size 384` if your GPU has enough memory.

## 1. Environment

Python 3.12 is supported. In VS Code, open a terminal in this `Assignment2` directory.

Create and activate a virtual environment:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
```

Install PyTorch and torchvision using the command recommended by the official selector for your machine:
<https://pytorch.org/get-started/locally/>

Then install the remaining project dependencies:

```bash
python -m pip install -r requirements.txt
```

Check whether CUDA is available:

```bash
python -c "import torch; print('PyTorch:', torch.__version__); print('CUDA available:', torch.cuda.is_available()); print('GPU:', torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'CPU')"
```

If CUDA is unavailable, Lightning will run on CPU, but training will be slower. `nvidia-smi` not being found often means the current environment does not expose NVIDIA's command-line utility; the PyTorch check above is the more relevant test for this script.

## 2. Download and inspect the data

The visualization script expects the data under `<root>/oxford-iiit-pet/`. The first run of the training script can download the dataset automatically. To inspect the dataset first, use the same Python environment:

```bash
python oxpet_download_and_viz_fixed.py --root ./data --split trainval --classes trimap --n 12 --resize 256
```

If this reports that the dataset is missing, download it through the training script once:

```bash
python src/train.py --root ./data --epochs 1 --limit-train 8 --limit-val 4 --run-name smoke-test
```

Then rerun the visualization command. The smoke test is only to check the pipeline, not a valid experiment.

## 3. Baseline and two improvements

Use the same split seed and training settings for comparable runs. The default train/validation split is 80/20 of the official `trainval` split. The official `test` split is not used for model development.

### Baseline: no random augmentation, cross-entropy loss

```bash
python src/train.py --root ./data --epochs 20 --batch-size 16 --image-size 256 --loss ce --run-name baseline
```

### Improvement 1: paired random augmentation

```bash
python src/train.py --root ./data --epochs 20 --batch-size 16 --image-size 256 --augmentation --loss ce --run-name augmentation
```

### Improvement 2: combined cross-entropy + soft Dice loss

```bash
python src/train.py --root ./data --epochs 20 --batch-size 16 --image-size 256 --loss ce_dice --run-name ce-dice
```

If the environment is slow or memory-limited, start with 5–10 epochs and batch size 4 or 8, then explain the adjustment in the report. The assignment allows up to 10 hours of GPU time; do not assume that all runs will need 20 epochs.

The code uses an ImageNet-pretrained ResNet-34 encoder by default. Its weights are downloaded on the first run if they are not already cached. If you need to run offline, add `--no-pretrained`.

## 5. Evaluate and create qualitative figures

Use the best validation checkpoint from a run. Replace the path below with the exact `.ckpt` path printed by training:

```bash
python src/viz.py --root ./data --checkpoint outputs/checkpoints/baseline-best.ckpt --split test --n 12
```

This reports overall and per-class IoU/Dice and writes a grid plus individual comparisons to `outputs/samples/`. If the assignment expects final test reporting, choose the model using validation metrics first and evaluate the selected checkpoint on the test split only after experiment decisions are complete.

## 6. Outputs

- `outputs/checkpoints/`: best Lightning checkpoint(s), selected by validation mIoU.
- `outputs/logs/`: CSV logs for training curves.
- `outputs/samples/`: exploration grid and prediction/ground-truth comparisons.
- W&B dashboard: available only for runs launched with `--wandb` after account authentication.
